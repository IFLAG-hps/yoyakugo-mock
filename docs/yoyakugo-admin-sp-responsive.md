# 予約GO 管理画面（B画面）スマートフォン対応 ─ 調整内容

**対象**：`B画面(管理画面)ph.3`
**作成日**：2026年8月17日
**目的**：スマホで管理画面が操作できない件について、原因の切り分け結果と、こちらで作成したレスポンシブ対応モックの内容を共有する

---

## 1. まず結論

いただいた質問（「動作しないのか」「UIが使いにくいのか」）への回答です。

**両方ですが、原因はほぼ1点に集約されています。**

- スマホでは**レイアウトが崩れて操作できない状態**になっています。これはJavaScriptの不具合ではなく、CSSのレイアウト指定が原因です。
- 加えて、PCと同じ見た目で表示できたとしても、**文字とボタンが小さすぎて実用に耐えません**。

ただし調べたところ、**全画面をゼロから作り直す必要はありません**。崩れの原因は共通CSSの数か所で、そこを直したうえで、一覧表とフォームの見せ方を整えれば成立します。実際にこちらでモックを改修して動くところまで確認しました。

---

## 2. 現状の調査結果

### 2-1. 通常表示で操作できない理由

`style.css` の次の2つの指定が同時に効いています。

```css
/* 51行目付近 */
.main {
    width: calc(100vw - 220px);   /* 左メニュー200px + 余白20px を差し引く前提 */
}

/* 84行目 */
@media (max-width: 760px) {
    .app { grid-template-columns: 1fr }
    .sidebar { display: none }      /* ← 左メニューが消える */
    ...
}
```

iPhone（横390px）で実測すると、次の状態になります。

| 項目 | 実測値 |
|---|---|
| 画面幅 | 390px |
| 本文（`.main`）の幅 | **170px** |
| 左メニュー（`.sidebar`） | **`display: none`（非表示）** |

`calc(100vw - 220px)` は「左メニューの分を引く」計算ですが、760px以下では左メニュー自体が消えるため、**引く必要のない220pxを引いたまま**になります。結果、本文が画面の左半分（170px）に押し込まれ、右側は空白になります。左メニューも消えているため、他の画面へ移動する手段が一切なくなります。

いただいたキャプチャ（`予約GOキャプチャ-SPフォント通常.jpg`）は、まさにこの状態です。

### 2-2. フォントを縮小すると操作できるようになる理由

ブラウザの文字サイズを最小にすると、ブラウザがレイアウト幅をPC相当（980px前後）として扱うため、760pxの分岐に入らずPC版のレイアウトがそのまま表示されます。操作はできますが、PC用のサイズのまま縮小表示されているだけなので、実用的ではありません。

同じくiPhone幅での実測値です。

| 要素 | 対応前の実測サイズ | 目安 |
|---|---|---|
| 一覧の「編集」「コピー」ボタン | **52 × 32px** | 44px以上が推奨 |
| ページ送りボタン（« ‹ › »） | **30 × 31px** | 44px以上が推奨 |
| 検索入力欄の文字サイズ | **13.3px** | 16px未満はiOSが自動でページを拡大する |

タップ領域の目安は Apple の Human Interface Guidelines が 44×44pt、Google の Material Design が 48×48dp としています。現状はいずれも下回っています。

また、検索入力欄の文字が16px未満のため、**iOS Safari では入力欄をタップするたびにページが勝手に拡大**します。拡大したまま戻らないので、そのあとの操作がさらに難しくなります。

### 2-3. その他、スマホで幅が溢れる指定

全30画面を390px幅で走査したところ、次の箇所にPC前提の固定幅が入っていました。いずれも横スクロールの原因になります。

| ファイル | 指定 | 内容 |
|---|---|---|
| `style.css` 5012行 | `@container menu-main-section (max-width: 639px) { .main-section-body { min-width: 640px } }` | 幅が狭いときに逆に640pxまで広げている |
| `admin_resourceGroup.html` | `.results-table { min-width: 520px }` | 一覧表の最小幅 |
| `admin_multilang_manage.html` | `.search-form-label { width: 200px !important }` | ラベル幅の固定 |
| `admin_multilang_manage.html` | `.checkbox-group { grid-template-columns: repeat(4, 1fr) }` | 言語チェックボックスの4列固定 |
| `admin_operation_log.html` | `.oplog-search-grid-row { grid-template-columns: repeat(3, 1fr) }` | 検索条件の3列固定 |
| `style.css` 3080行 | `.search-form-label { min-width: 120px }` | ラベル幅の下限 |

## 3. モックで対応した内容

### 3-1. ファイル構成

**既存の `style.css` と各HTMLの中身は変更していません。** 追加ファイル2本と、各HTMLへの読み込み2行のみです。

| ファイル | 内容 | 状態 |
|---|---|---|
| `sp.css` | スマホ・タブレット向けの追加スタイル | 新規（約480行） |
| `sp.js` | ハンバーガー等の生成と、一覧表のラベル付与 | 新規（約230行） |
| `sp_preview.html` | 端末幅を指定して各画面を並べて確認できるページ | 新規（確認用） |
| 各HTML（30ファイル） | `</head>` の直前に2行追加 | 既存を2行だけ追記 |

各HTMLに追加した2行は次のとおりです。`style.css` より後に読み込みます。

```html
<link href="./sp.css" rel="stylesheet">
<script src="./sp.js" defer></script>
```

変更をすべてメディアクエリの中に閉じているため、**PC表示（1025px以上）は一切変わりません**。

### 3-2. ブレークポイント

既存CSSには 760px / 768px / 640px / 480px が混在していたので、追加分は2つに整理しました。

| 幅 | 切り替わる内容 |
|---|---|
| **1024px 以下** | 左メニューを引き出し（ハンバーガー）に。本文を全幅に。上部バー・下部タブを表示 |
| **768px 以下** | 一覧表をカード表示に。フォームを1カラムに。モーダルを全画面シートに |

（360px以下で文字詰めの微調整あり）

## 4. 画面別の変更内容

### 4-1. 共通：ナビゲーション

| 対応前 | 対応後 |
|---|---|
| 760px以下で左メニューが消え、画面移動ができない | 上部バーのハンバーガーで左メニューを開閉 |
| — | 暗幕タップ / ×ボタン / Escキー で閉じる。開いている間は背面をスクロールさせない |
| — | 下部に「ホーム / 受付・予約 / 顧客 / メニュー / すべて」のタブを追加。現在地をハイライト |
| PC用のヘッダーに「パスワード変更」「ログアウト」が並び、横に溢れる | この2つは引き出しの下部に移動。ヘッダーには各画面の操作（検索・新規登録など）のみ残す |
| メニュー項目の高さ 約40px | 48px に拡大 |

追加した上部バーの構造は次のとおりです（現状は `sp.js` が生成していますが、本実装ではテンプレートに直接書いていただく形を想定しています）。

```html
<header class="sp-appbar">
  <button type="button" class="sp-appbar-btn" id="spNavToggle"
          aria-label="メニューを開く" aria-expanded="false" aria-controls="spSidebar">
    <span class="sp-burger-icon"><span></span><span></span><span></span></span>
  </button>
  <span class="sp-appbar-title">メニュー管理</span>
</header>
<div class="sp-scrim" id="spScrim"></div>
```

### 4-2. 一覧画面：表をカード表示に

対象：受付・予約一覧 / 顧客管理 / メニュー管理 / スタッフ管理 / リソース管理 / リソースグループ / 操作履歴 / 利用料金

横に長い表は、768px以下で **1行 = 1カード** に組み替えます。見出し行（`<thead>`）は読み上げ用に残したまま視覚的に隠し、各セルの左側に項目名を表示します。

```
【対応前】横スクロールしないと読めない
┌────┬──────────┬────────┬────────┬────────┬──────────┐
│ ID │ メニュー名   │ 料金    │ 所要時間 │ WEB受付 │ 操作      │
├────┼──────────┼────────┼────────┼────────┼──────────┤
│ 1  │ カット      │ 4,000円 │ 60分    │ 受け付ける │ 編集 コピー │
└────┴──────────┴────────┴────────┴────────┴──────────┘

【対応後】カードで縦に読める
┌──────────────────────────┐
│ ● カット                    │  ← メニュー名を見出しに
│ ID 1                        │
│ ─────────────────────────  │
│ 料金(税込)   4,000円          │
│ 所要時間     60分             │
│ WEB受付      受け付ける        │
│ ─────────────────────────  │
│ [   編集   ] [  コピー  ]     │  ← 操作はカード末尾に、44px以上で
└──────────────────────────┘
```

項目名は `<td>` の `data-label` 属性を CSS の `::before` で表示しています。

```css
.results-table tbody td::before {
    content: attr(data-label);
    color: var(--muted);
    font-size: 12px;
    font-weight: 600;
}
```

モックでは `sp.js` が `<thead>` の見出しテキストを読み取って `data-label` を自動で付けています。カードの見出しにする列は「名」「件名」「タイトル」を含む見出しから自動判定、ID列と操作列も見出し名から判定しています。

**見出しに結合セル（colspan）がある表は、カード化に向かないので対象外**とし、従来どおり横スクロールにしています（`sp.js` が `.sp-no-card` を付与）。営業時間の設定表と利用料金の契約内容表も、項目数が多く縦に伸びすぎるため横スクロールのままにしています。

### 4-3. 受付・予約管理（スケジュール表）

時間 × リソースの表は性質上そのまま残しますが、以下を調整しました。

- スマホ幅では**初期表示を「1週間」から「1日」に変更**（1週間 × リソース5件 = 35列は横に長すぎるため）
- 日付ツールバーを2段に整理（1段目：日付欄を全幅／2段目：前日・今日・翌日を3等分）
- 表の高さ固定（`height: calc(100vh)`）を解除。表の中だけを横スクロールできるように

### 4-4. フォーム画面

対象：基本設定 / シフト設定 / 多言語管理 / パスワード変更 / 各種検索条件

| 対応前 | 対応後 |
|---|---|
| ラベル（120〜200px固定）と入力欄が横並びで、画面幅を超える | ラベルを入力欄の上に置いて縦積み |
| 入力欄の文字が13〜14px → iOSで入力時にページが拡大する | **16px に統一**（拡大されなくなる） |
| 入力欄の高さ 38px | 44px 以上 |
| 検索条件の3列・4列グリッド | 1列（チェックボックス群のみ画面幅に応じて自動折り返し） |
| ボタンが横並びで潰れる | 縦積み・全幅 |

### 4-5. モーダル（受付・予約一覧、各種登録・編集）

`width: 80vw; height: 80vh` の中央モーダルは、スマホでは中身が読めないため**全画面シート**にしました。

- 画面いっぱい（`100dvh`）に表示。角丸なし
- ヘッダー（タイトル＋×ボタン）を上部に固定
- 保存・キャンセルなどのボタンを下部に固定し、全幅・48px以上に
- 下部タブより前面に出るよう `z-index` を調整

### 4-6. ダッシュボード

- 2カラムのカード（今日の受付・予約／空き枠）を縦積みに
- カード見出しと右肩の補足（件数・最終更新）が潰れていたので折り返すように
- 予約1件あたりの表示を「時刻」「内容」「ステータス」の縦積みに

## 5. 修正の要点（優先度順）

本実装で手を入れる際、効果が大きい順に3点です。**この3点だけでも「操作できない」状態は解消します。**

### ① 本文の幅指定（最優先）

```css
/* 現状 */
.main { width: calc(100vw - 220px); }

/* 修正案：左メニューが消える幅では 100% に戻す */
@media (max-width: 1024px) {
    .main {
        width: 100%;
        max-width: 100%;
        /* 内側スクロール（max-height:100vh / overflow-y:auto）も解除し、
           ページ全体でスクロールさせる。スマホでアドレスバーが隠れるようになります */
        max-height: none;
        height: auto;
        overflow: visible;
    }
}
```

### ② 左メニューを消さず、引き出しにする

```css
/* 現状：760px以下で消えてしまう */
@media (max-width: 760px) { .sidebar { display: none } }

/* 修正案：画面外に置いておき、ハンバーガーでスライドさせる */
@media (max-width: 1024px) {
    .sidebar {
        display: flex;
        position: fixed; top: 0; left: 0; bottom: 0;
        width: 276px; max-width: 84vw;
        z-index: 1300;
        overflow-y: auto;
        transform: translateX(-100%);
        transition: transform .24s cubic-bezier(.4, 0, .2, 1);
    }
    body.sp-nav-open .sidebar { transform: translateX(0); }
}
```

### ③ 入力欄の文字サイズを16px以上に

```css
@media (max-width: 768px) {
    input, select, textarea, .form-input {
        font-size: 16px !important;
        min-height: 44px;
    }
}
```

iOS Safari は16px未満の入力欄をタップすると自動でページを拡大します。1行の指定ですが、体感の改善は大きい部分です。

## 6. 本実装にあたってのお願い・補足

### 6-1. `sp.js` の役割について

モックでは既存HTMLを書き換えずに済ませるため、以下の2つをJavaScriptで行っています。

1. 上部バー・暗幕・下部タブの生成
2. 一覧表の `<td>` への `data-label` 付与

**本実装では、この2つはサーバー側のテンプレートに直接書いていただくほうが素直です。**

```html
<!-- 一覧表：出力時に data-label を付ける -->
<td data-label="料金(税込)">4,000円</td>
<td data-label="所要時間">60分</td>
<td class="action-cell">
  <button class="link-btn">編集</button>
  <button class="link-btn">コピー</button>
</td>
```

テンプレートに書けば `sp.js` は開閉の処理だけになり、40行程度まで減らせます。JavaScriptが無効でもカード表示が成立するのも利点です。

### 6-2. 既存CSS側で直したほうがよい箇所

`sp.css` では後勝ちや `!important` で打ち消していますが、本実装では元の指定を見直していただくほうがすっきりします。

- `style.css` 51行 `.main { width: calc(100vw - 220px) }`
- `style.css` 84行 `@media (max-width:760px) { .sidebar { display:none } }`
- `style.css` 5012行 コンテナクエリの `min-width: 640px`
- 各HTMLの `<style>` 内にある `width: ...px !important` / 列数固定のグリッド（2-3の表を参照）
- ブレークポイントの統一（760 / 768 / 640 / 480 が混在しています）

### 6-3. ダッシュボードのカード見出しについて

現状 `admin_index.html` のカード見出しは `style="display:flex; justify-content:space-between"` のインラインスタイルで組まれています。`sp.css` では属性セレクタ（`[style*="space-between"]`）で拾って折り返していますが、**`.card-head` のようなクラスを付けていただければ普通のセレクタで指定できます**。

### 6-4. 対応していない項目

以下は今回のモックには含めていません。必要かどうかご相談させてください。

| 項目 | 現状 | 備考 |
|---|---|---|
| シフト設定の月カレンダー | 7列のまま文字を小さくして対応 | スマホでは日別リスト表示のほうが実用的と思われるので、別途ご相談したいです |
| 受付・予約のスケジュール表 | 「1日」表示＋横スクロール | 縦軸=時間／横軸=リソース の構造自体は変えていません |
| スワイプでの引き出し操作 | 未対応（タップのみ） | あると便利ですが必須ではないと考えています |
| 引き出し内のフォーカストラップ | 未対応 | キーボード操作の厳密な閉じ込め |
| 一覧のスワイプ操作（左スワイプで編集など） | 未対応 | 誤操作のリスクもあるため見送りました |

## 7. 確認方法

`B画面(管理画面)ph.3/sp_preview.html` をブラウザで開くと、主要7画面を実機と同じ幅（CSSピクセル）で並べて確認できます。右上のプルダウンで端末幅（iPhone / Android / タブレット）を切り替えられます。枠の中はそのまま操作できます。

個別の画面を見る場合は、Chrome の DevTools（F12 → 端末ツールバー）で幅を 390px にしてご確認ください。

確認のポイント：

1. ハンバーガーで左メニューが開き、暗幕タップで閉じるか
2. 一覧がカード表示になっているか
3. ボタンが指で押せる大きさになっているか（44px以上）
4. 横スクロールが発生していないか

全30画面を390px幅で自動チェックし、**ページ全体の横はみ出しが無いことは確認済み**です（スケジュール表・営業時間表・タブなど、意図的に横スクロールさせている箇所を除く）。
